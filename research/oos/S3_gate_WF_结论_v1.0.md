# S3 状态门控样本外检验结论（WF 因果状态）v1.0

**日期**: 2026-10-10
**脚本**: `research/oos/s3_gate_oos_wf_v1_0.py`，报告 `S3_gate_WF_OOS_report_v1_0.md`
**状态来源**: `WF_4H_rule_states.csv`（walk-forward 规则引擎，4 状态，无 TRANSITION）
**对齐**: 开仓时刻 E 取最后一根已收盘 4H bar（dt = E-4h）。dt 为 K 线开盘时间，收盘在 dt+4h；取 dt = E 会引入一根未收盘 bar 的前视，仅作敏感性对照。
**切分与规则**: 切分 2024-01-01；规则只用 IS 确定，即排除 IS 内均笔 R < 0 的状态。

---

## 0. 结论（更正上一份结论）

1. **门控的样本外收益在因果状态下消失。** 排除 TREND_DOWN 后，OOS 期末由 5.97x 变为 5.39x，均笔 R 基本不变（+0.379 → +0.386），最大回撤不变。
2. **上一份结论（OOS 7.39x）不能采信。** 那个结果用的是 hybrid 状态，其因果性无法验证。在因果状态下，同一规则没有带来样本外改善。
3. **TREND_DOWN 在因果状态下几乎不出现在开仓时。** 183 笔中只有 7 笔开仓时状态为 TREND_DOWN（IS 3 笔、OOS 4 笔），原 hybrid 状态则有 39 笔。IS 中用于定规则的只有 3 笔（均笔 R -0.617），样本太小，无法支撑任何规则。
4. **门控在因果状态下没有证据支持，建议放弃。**

## 2. 敏感性（前视，dt = E）

仅供对照。取 dt = E 时，IS 中 TREND_UP 出现 3 笔、均笔 R +3.123，结果随对齐方式剧烈变化，说明开仓时刻若取到未收盘的 bar，结论会被明显扭曲。OOS 门控后为 5.81x，同样不支持门控。

## 3. 与原 hybrid 状态的对照

同一脚本的对照组（原 `S1_trades_with_states.csv` 中的 hybrid 状态）仍给出 OOS 7.39x 的门控结果。两套状态的开仓标签只有约 67–69% 一致，因此门控的“改善”高度依赖具体的状态来源。

## 4. 局限

| 问题 | 影响 |
|---|---|
| WF 状态是规则引擎（v1.0），不是项目实际使用的 hybrid | 本次检验的是规则状态的门控，不是 hybrid 门控。hybrid 的因果性仍未验证。 |
| 因果性依赖文件名与生成流程 | 我没有重算 WF 的特征，只是按文件名与对齐逻辑假定其为因果。若要确认，需要重跑 walk-forward 流程。 |
| TREND_DOWN 开仓样本极少 | 无论哪种口径，门控的统计功效都很低。 |
| 状态与 DEF1 的关系 | `PROJECT_STATUS.md` 记录 TREND_DOWN 语义是「暴跌后反弹」，本次 7 笔的结果与该语义也不一致，需要进一步研究。 |

---

## 5. 建议

1. 不把状态门控作为 S1 的过滤条件。
2. 若要继续研究状态，应先确认 hybrid 的因果性，并把 TREND_DOWN 的定义问题（DEF1）单独解决。
3. 对 `PROJECT_STATUS.md` 中“门控 457→943U”的表述，应注明它是样本内、含前视的结果。
