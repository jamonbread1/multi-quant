# S1 提速研究结论 v1.0

**日期**: 2026-10-10
**研究动机**: 收益增长太慢、错过很多行情（做状态机的初衷）。
**脚本**: `swing_capture_v1_0.py`（机会捕获）、`s1_engine_v1_0.py`（引擎）、`s1_engine_recon_v1_0.py`（对账）、`s1_speed_variants_v1_0.py`（提速变体）
**报告**: `swing_capture_report_v1_0.md`、`s1_engine_recon_v1_0.md`、`S1_speed_variants_report_v1_0.md`

---

## 0. 结论先行

1. **你的直觉有数据支持：S1 确实错过了大部分行情。** ETH 大波段（≥25% 的 zigzag 腿）中，S1 只捕获了约 16% 的对数收益，进场中位延迟约 8 天，与 48 根 4H 通道（8 天）直接对应。
2. **但缩短入场通道并不能提速复利。** 通道减半或缩到 16 根后，进场延迟降到 2–4 天，捕获率升到 23–24%，但胜率从 44% 降到 33%，交易笔数翻倍，最大回撤从 -63% 恶化到 -89%，期末资产反而更少。
3. **瓶颈不是进场慢，而是震荡市里的假信号。** 更快的入场同时带来更多假突破。收益速度的代价是回撤，目前的参数组合里没有“又快又稳”的点。
4. **关闭 ADX 门控（V3）对结果几乎没有影响**（期末 299U vs 315U），ADX 门控不是拖慢 S1 的主因。
5. **所有之前的 S1 结论都要改用净口径。** 日志的 `pnl_u` 是毛利，未扣手续费；权益按扣费后复利。之前报告的 457U、OOS 5.97x 都是毛利口径，净值更低（见第 3 节）。

## 1. 机会捕获（为什么觉得慢）

大波段定义：ETH 4H 收盘价的 zigzag 腿，幅度 ≥ 25%（事后测量尺，含前瞻）。全样本 40 条腿，上涨 20、下跌 20。

| 指标 | 数值 |
|---|---|
| 进场中位延迟（相对腿起点） | 7.8 天 |
| 按腿对数收益加权的捕获率 | 16.4% |
| 完全错过的腿 | 2 / 40 |
| 持仓覆盖率（腿内同向持仓占比） | 16.6% |

S1 在大行情中并非完全踏空，而是进场晚、持仓时间短，大部分利润在入场前已经发生。

## 3. 引擎对账（结论可信度）

研究引擎复刻了 FMZ 源码的执行语义，逐笔对账结果：

| 项目 | 结果 |
|---|---|
| 入场时间与方向 | 183 / 183 完全一致 |
| 离场时间 | 183 / 183 完全一致 |
| 入场价 | 中位偏差 0.000%，最大 0.00% |
| 离场价 | 中位偏差约 0.0004%（止损为市价单，成交在下一根开盘附近） |
| 单笔毛利 | 中位偏差 1.3%，最大 8.9% |
| 权益路径 | 中位偏差 1.6%，最大 5.0% |
| 期末权益 | 引擎 315U vs 日志 371U（差约 -15%） |

**残余偏差的来源（未完全解决）**：日志中的市价成交价与开盘价有少量差异；资金费计提口径可能与交易所略有不同。剩余的 15% 偏差主要来自复利过程中的小误差累积。因此：
- 引擎适合做同一口径下的参数对比；
- 绝对收益水平应视为有约 ±15% 的不确定性。

**对账过程中修正的 5 处源码语义（都已写进引擎注释）**：
1. 吊灯抬升用的是上一根收盘 K 线的高/低点（`h[-2]`），不是最新一根；
2. 入场、信号离场、仓位计算用的是信号 K 线的收盘价（`px = c[-1]`）；
3. 止损是市价单，成交在下一根开盘附近；
4. 预热期是 198 根（48 根通道 + 150 根 ADX 收敛），且数据需要从 2019-12 开始；
5. 日志的 `pnl_u` 是毛利，权益复利扣手续费（taker 0.05%/边）。

## 5. 对“状态机能否提速”的回答

- 状态机的目标是“在对的时候用对的策略”，这次测试的是更快入场（通道缩短），结论是**提速入场会增加假信号，净效果为负**。
- 所以“提速”不能靠更灵敏的入场规则来实现。状态机若要有价值，必须同时降低震荡市的假突破（即减少 V1/V2 那样的亏损交易），而不是只让入场更快。
- 目前已测的状态门控（排除 TREND_DOWN）在因果状态下没有样本外改善，与此一致：**状态门控目前没有证据能同时提速并控制回撤。**

## 6. 局限

| 问题 | 说明 |
|---|---|
| 样本内外不对称 | 所有变体的 OOS 都优于 IS，OOS 集中在 2024–2026 的强趋势段，不代表稳定优势。 |
| 大波段定义含前瞻 | 仅用于测量捕获率，不能用于交易决策。 |
| 只测了入场通道与 ADX | 未测试杠杆、出场规则、状态机本身。杠杆会线性放大回撤，且引擎未模拟强平。 |
| 引擎残余偏差约 15% | 见第 3 节。 |
| 样本仅 ETH 单标的 | 无法分散；ZEC 已关闭，其它标的需要重新获取数据。 |

---

## 7. 建议的下一步

1. **明确“提速”的目标**：是提高年化，还是降低回撤后再加杠杆？两者路径不同，需要先选一个。
2. **若要研究减少假突破**：在 V0 上检验出场规则（如止损宽度、吊灯倍数），而不是进一步缩短通道。
3. **若要研究状态机**：先在净口径下重做 S3 门控检验，确认前提成立，再考虑在状态层面做差异化策略。
4. **补充标的**：ETH 单标的样本量有限，建议获取 BTC 等其它标的的 4H 数据做同样的检验。
